## Migration hardening
The G2 CI gate now verifies:
1. exactly one Alembic head exists;
2. a clean PostgreSQL database can upgrade from base to head;
3. `alembic current` resolves the expected head;
4. `alembic check` finds no pending model/schema operations;
5. the entire migration chain can downgrade to base;
6. the same database can replay all migrations back to head;
7. a second `alembic check` remains clean after replay.

## Drift discovered by G2.8
The first hardening run correctly failed `alembic check`.

Detected difference:
- persisted migration index: `ix_iam_assignment_user_id`;
- ORM-generated expectation from `index=True`: `ix_iam_user_role_assignment_user_id`;
- persisted migration index: `ix_iam_assignment_role_id`;
- ORM-generated expectation from `index=True`: `ix_iam_user_role_assignment_role_id`.

The physical database schema was already correct and stable. The defect was metadata naming drift.

Remediation:
- explicit `Index("ix_iam_assignment_user_id", "user_id")`;
- explicit `Index("ix_iam_assignment_role_id", "role_id")`;
- removal of the two implicit `index=True` declarations.

No new migration was created because no physical schema change was required.
