# G2.2 Evidence — Product Configurations

Date: 2026-10-29  
Gate: G2 — Master Data  
Slice: G2.2 — Product configurations  
Status: **COMPLETED**

## Objective
Represent commercial/manufacturing product configuration without creating a second product identity.

The authoritative identity remains the exact `Article`; later BOM and Routing/BOP continue to bind to exact Article/ArticleRevision records.

## Persistence
G2.2 adds:

`md_product_configuration`

Fields:
- id;
- article_id;
- family_code / family_name;
- model_code / model_name;
- class;
- width;
- width_uom_id;
- configuration_string;
- active;
- created_at / updated_at.

## Identity and cardinality
`article_id` is unique.

Therefore:
- one exact finished Article has at most one ProductConfiguration projection;
- multiple exact Articles may belong to the same family/model;
- family/model metadata does not replace Article identity;
- configuration text does not become a BOM or Routing key.

## Finished-product rule
A ProductConfiguration may only reference an Article whose `article_kind` is:

`FINISHED_PRODUCT`

Attaching commercial configuration metadata to purchased/manufactured intermediate components is rejected with HTTP 422.

## Width semantics
Width is optional. When present:
- it is stored as Decimal `NUMERIC(12,4)`;
- `width_uom_id` is mandatory;
- the UoM must exist;
- the UoM must be active;
- the UoM must be canonical;
- the UoM dimension must be `LENGTH`.

The database also enforces:
- positive width;
- width and width_uom_id are either both null or both present.

This prevents unitless manufacturing dimensions.

## API
Added:
- `POST /api/v1/master-data/product-configurations`;
- `GET /api/v1/master-data/product-configurations`;
- `GET /api/v1/master-data/articles/{article_id}/product-configuration`.

List filtering supports:
- family_code;
- model_code;
- active.

All endpoints use the existing `masterdata.read` / `masterdata.edit` capabilities.

## Audit
Creation emits:

`masterdata.product_configuration.create`

into the append-only G1 audit substrate.

Audit details include:
- Article ID;
- family code;
- model code;
- product class.

## Frontend
The permission-driven shell now exposes:

`Datos maestros`

for users with `masterdata.read` or `masterdata.edit`.

The G2.2 baseline view lists active configurations with:
- family;
- model;
- class;
- width and canonical UoM;
- configuration string.

The surface is read-only in this slice. Creation remains API-governed until a later Master Data editing workflow is defined.

## Boundaries
G2.2 does not:
- duplicate Article identity;
- attach BOM/Routing directly to family/model;
- infer configuration from Article code prefixes;
- hard-code FAIC-specific upholstery/electronics dimensions into the generic canonical schema;
- expose mutation forms in the frontend;
- alter historical ArticleRevision behavior.
