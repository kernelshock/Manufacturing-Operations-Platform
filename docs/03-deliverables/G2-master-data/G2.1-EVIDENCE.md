## Implemented
G2.1 establishes the canonical identities required by all later manufacturing-definition slices:

- `md_uom`;
- `md_uom_alias`;
- `md_article`;
- `md_article_revision`.

The implementation follows the G0 physical-schema baseline and does not duplicate G1 organizational resources.

## Article identity
Article identity is globally unique per:

`external_system + external_code`

The article kind is explicit and is not inferred from code prefixes.

Supported baseline kinds:
- UNKNOWN;
- PURCHASED;
- MANUFACTURED;
- FINISHED_PRODUCT;
- CONSUMABLE;
- SERVICE.

This preserves AC-02 and AC-03 from the Prolowin assimilation requirements.

## Article revisions
A new ArticleRevision:
- references the exact Article identity;
- stores a 64-character source fingerprint;
- starts in `DRAFT`;
- has effectivity timestamps;
- can retain a future source-batch identifier;
- does not overwrite historical revisions.

Direct activation/promotion is intentionally not part of G2.1.

## Units of measure
Canonical UoM records carry:
- code;
- dimension;
- canonical flag;
- active flag.

Source aliases preserve:
- source system;
- raw source text;
- optional approved canonical UoM;
- mapping status;
- optional Decimal conversion factor;
- approver/timestamp when mapped.

A source value is never silently discarded or rewritten.

## RBAC
Migration `0006_g2_1` adds:
- `masterdata.read`;
- `masterdata.edit`.

The built-in ADMIN role receives both permissions.

Integration tests verify that a read-only Master Data role can list canonical data but receives HTTP 403 on create operations.

## Audit
The following write actions enter the immutable G1 audit substrate:
- `masterdata.uom.create`;
- `masterdata.uom_alias.create`;
- `masterdata.article.create`;
- `masterdata.article_revision.create`.

No separate Master Data audit table is introduced.

## API
Baseline endpoints:
- `POST/GET /api/v1/master-data/uoms`;
- `POST/GET /api/v1/master-data/uom-aliases`;
- `POST/GET /api/v1/master-data/articles`;
- `POST/GET /api/v1/master-data/articles/{article_id}/revisions`.

No delete endpoint exists for manufacturing-definition history.

## Boundary
G2.1 creates identity and revision foundations only.

It does not yet:
- model product configuration/variants;
- model suppliers;
- author BOM relations;
- author Routing/BOP;
- define manufacturing calendars;
- parse Prolowin reports;
- approve/promote candidate article revisions.

Those capabilities remain in G2.2–G2.8.
