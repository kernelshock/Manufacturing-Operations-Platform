## Setup evidence

New `ExecutionSetup` supports one optional setup cycle per execution operation.

Rules:
- setup can only start from a RELEASED dispatch;
- setup can only start while the operation remains PENDING;
- setup start/finish timestamps are explicit;
- setup finish cannot precede setup start;
- operation START is blocked while setup remains open;
- repeated identical setup actions are idempotent;
- setup does not alter G4 planned timestamps.

## Pause / resume / interruption evidence

New `ExecutionInterruption` supports repeatable interruption cycles.

Operation lifecycle now supports:

`PENDING → RUNNING ↔ PAUSED → COMPLETED`

Rules:
- only RUNNING operations can pause;
- only PAUSED operations with an open interruption can resume;
- COMPLETE remains blocked while PAUSED;
- interruption start cannot precede actual operation start;
- resume cannot precede interruption start;
- each interruption requires an explicit non-empty `reason_code`;
- optional reason notes remain operator evidence;
- database partial uniqueness guarantees at most one open interruption per operation;
- multiple closed interruptions are allowed and preserved historically.

## Actual resource / resource deviation

G5.3 adds:
- `actual_resource_id`;
- `resource_deviation_reason`.

Rules:
- actual resource remains unknown unless explicitly supplied;
- supplied resource must exist and be active;
- if actual resource differs from planned resource, a deviation reason is mandatory;
- if actual resource equals planned resource, a deviation reason is rejected;
- resource deviation does not rewrite the G4 planned resource.

This records execution truth without inventing resource identity.

## Deviation projection

`GET /api/v1/mes/operations/{operation_id}/deviation` derives:

- planned vs actual start delta;
- planned vs actual finish delta;
- requested vs produced quantity delta;
- planned vs actual resource deviation;
- completed setup duration;
- accumulated closed-interruption duration;
- whether an interruption remains open.

These are observational metrics only.

G5.3 does **not** automatically classify a delay as:
- maintenance;
- material;
- workforce;
- quality;
- any other causal domain.

Causality remains explicit evidence supplied through interruption reasons or later authoritative gates.
