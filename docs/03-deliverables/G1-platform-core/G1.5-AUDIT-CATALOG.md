# G1.5 Audit Action Catalog

Status: baseline implemented  
Date: 2026-10-28

## Purpose
This catalog defines the action identifiers emitted by the G1.5 audit baseline. Action identifiers are stable machine-readable contracts; presentation labels may evolve independently.

## Authentication
| Action | Object type | Outcome |
|---|---|---|
| `auth.login.success` | `user_session` | success |
| `auth.login.failure` | `user_session` | failure |
| `auth.logout` | `user_session` | success |

Failed login records may contain the normalized attempted username and a non-sensitive reason code. Passwords, password hashes and raw session tokens are prohibited from audit details.

## Audit event envelope
Each event can carry:
- immutable UUID;
- UTC/tz-aware occurrence timestamp;
- actor user UUID when known;
- actor username snapshot;
- stable action code;
- object type and object identifier;
- scope type and scope identifier;
- outcome;
- request correlation identifier;
- source IP;
- structured JSON details.

## Immutability rule
`audit_event` is append-only at the database layer. PostgreSQL rejects UPDATE and DELETE through `trg_audit_event_append_only`.

Corrections must be represented by a later event. Existing events are never rewritten.

## Read access
Audit events are available only through the read-only API:

`GET /api/v1/audit/events`

The caller requires global `audit.read` permission. G1.5 provides no create/update/delete audit API.
