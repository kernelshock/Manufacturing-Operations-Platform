## Persistence rules
- immutable internal UUID primary keys;
- business codes stored separately from internal IDs;
- organization code unique per deployment;
- plant code unique within organization;
- area code unique within plant;
- work-center code unique within area;
- resource code unique within work center;
- parent relationships enforced by PostgreSQL foreign keys;
- parent existence validated at the application-service boundary;
- duplicate business codes produce an explicit conflict rather than silent overwrite.

## API baseline
Versioned endpoints are exposed under `/api/v1/core` for create/list operations on:
- organizations;
- plants;
- areas;
- work centers;
- resources.

The API supports parent-scoped listing and returns 404 for missing parents and 409 for contextual business-code conflicts.
