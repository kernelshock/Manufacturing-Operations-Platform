Gate: G1 — Platform Core  
Slice: G1.7 — Runtime  
Status: **COMPLETED**

## Implemented runtime

G1.7 packages the Platform Core as a reproducible Docker Compose DEV/TEST stack:

```text
Browser
  |
  v
nginx / React frontend
  |
  +--> /api
  +--> /health
  +--> /docs
          |
          v
      FastAPI API
          |
          v
      PostgreSQL 18
```

Only the frontend/reverse-proxy port is published by the Compose baseline. PostgreSQL and FastAPI remain on internal Docker networks.

## Startup ordering

The runtime enforces:

1. PostgreSQL container starts;
2. PostgreSQL health check passes;
3. one-shot `migrate` service executes `python -m alembic upgrade head`;
4. API starts only after migration success;
5. API readiness verifies PostgreSQL;
6. frontend/reverse proxy starts only after API health succeeds.

This prevents serving the application against an outdated or unavailable schema.

## Runtime configuration and secrets

Committed files contain examples only. Runtime credentials are supplied through an ignored env file or process environment.

The backend now supports discrete database settings:
- host;
- port;
- database;
- user;
- password.

SQLAlchemy constructs and safely encodes the PostgreSQL URL. Automated tests include a password containing URI-special characters and verify the resulting URL preserves the original credential without plaintext string interpolation.

The first administrator remains an explicit one-shot operation through the `bootstrap-admin` service. Its password is not committed to the repository.

## Public boundary

DEV/TEST Compose binds only the nginx/frontend service to loopback. nginx:
- serves the React production build;
- proxies `/api`, `/health`, `/docs` and OpenAPI to FastAPI;
- generates/preserves request IDs;
- forwards client address headers.

FastAPI is not published directly in the Compose runtime. Uvicorn proxy-header trust is therefore constrained to the internal reverse-proxy topology.

## PostgreSQL 18 volume correction

The initial runtime smoke in run #83 failed before MOP startup because the Compose file used the historical PostgreSQL volume target `/var/lib/postgresql/data`.

PostgreSQL 18 changed the official image layout. The named volume was corrected to:

`/var/lib/postgresql`

Run #85 validated the corrected topology successfully.

## CI runtime smoke

3. creates a fresh PostgreSQL volume;
4. waits for PostgreSQL health;
5. applies all Alembic migrations;
6. starts the API;
7. waits for `/health/ready` through nginx;
8. verifies the React application is served;
9. bootstraps an ephemeral administrator;

12. validates audit access;
13. destroys the test volume.

Result: **MOP runtime smoke test passed.**

## Local operator commands

Create an ignored runtime configuration:

```bash
cp infrastructure/config/runtime.dev.env.example .env.runtime
```

Set `MOP_POSTGRES_PASSWORD`, then:

```bash
./infrastructure/scripts/runtime-dev-up.sh
```

Create the initial administrator:

```bash
./infrastructure/scripts/runtime-bootstrap-admin.sh
```

Stop while preserving PostgreSQL data:

```bash
./infrastructure/scripts/runtime-dev-down.sh
```

## Explicit boundary

This is a DEV/TEST runtime baseline. ADR-0015 still requires HTTPS for the plant-network production topology.

Container image digest pinning is deferred to G1.8 hardening. A background worker is not fabricated in G1.7 because no persistent job/outbox worker contract exists yet.
