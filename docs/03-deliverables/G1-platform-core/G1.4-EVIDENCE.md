## Implemented identity model
- individual local user accounts;
- normalized unique usernames;
- enabled/disabled account state;
- password hashes only; plaintext credentials are never persisted or returned;
- built-in ADMIN system role;
- seeded capability permission catalog;
- configurable roles and permission grants;
- scoped user-role assignments.

## Password security
Passwords are hashed with Argon2 through `pwdlib[argon2]`. The test suite verifies that stored hashes use the Argon2 format, do not contain the plaintext password and correctly reject invalid credentials.

## Web session model
Authentication uses opaque random session tokens:
- the browser receives only the raw opaque token in an HttpOnly cookie;
- the database stores only a SHA-256 digest of the random session token;
- sessions carry explicit expiry and revocation timestamps;
- production/shadow/parallel stages force the cookie `Secure` flag;
- the cookie uses `SameSite=Strict` in the local-auth baseline;
- logout revokes the server-side session and deletes the browser cookie.

## RBAC scope model
Assignments support:
- global;
- organization;
- plant;
- area.

Permission evaluation is hierarchical. A role scoped to an organization may operate on descendant plants/areas/work centers/resources only when its permission grants that capability. It cannot escape to another organization or gain global access.

## Protected API
The `/api/v1/core` organizational endpoints now require authentication and capability authorization. IAM administration endpoints require global `admin.users` or `admin.roles` permission.

Authentication endpoints:
- `POST /api/v1/auth/login`;
- `POST /api/v1/auth/logout`;
- `GET /api/v1/auth/me`.

IAM administration baseline:
- users;
- roles;
- seeded permissions;
- role-permission grants;
- scoped user-role assignments.

## Initial administrator bootstrap
No public registration route is provided. After migrations, the first global administrator is created interactively with:

```bash
python -m mop.cli.bootstrap_admin
```

The password is read without echo. Automation may supply `MOP_BOOTSTRAP_ADMIN_PASSWORD`; it must not be committed to the repository.
