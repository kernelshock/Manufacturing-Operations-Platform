## Authentication hardening
G1.8 adds persistent login-failure state to local user identities:
- default maximum consecutive failures: 5;
- default lockout period: 15 minutes;
- lockout stored in PostgreSQL, not process memory;
- successful authentication resets failure count and lock;
- unknown usernames still execute an Argon2 verification against a dummy hash to reduce username-existence timing differences;
- client-facing failures remain the same generic `invalid credentials` response.

Integration tests validate lock, rejection of the correct password while locked, expiry and successful reset.

## HTTP and reverse-proxy hardening
nginx now:
- suppresses server version tokens;
- rate-limits the login endpoint;
- returns HTTP 429 when the limit is exceeded;
- sends `X-Content-Type-Options: nosniff`;
- sends `X-Frame-Options: DENY`;
- sends a restrictive Content Security Policy;
- sends restrictive Referrer/Permissions/COOP headers.

FastAPI marks authentication, IAM and audit responses `Cache-Control: no-store`.

The runtime smoke test validates these controls through the same reverse-proxy boundary used by the browser.

## Secret handling
A tracked-file secret baseline fails CI on:
- committed private-key material;
- literal PostgreSQL passwords;
- literal bootstrap-administrator passwords.

Dynamic runtime injection is allowed. Runtime smoke secrets are generated ephemerally with Python `secrets.token_urlsafe`.

The committed example configuration no longer contains a development database password in its default SQLAlchemy URL.

## Supply-chain reproducibility
G1.8 pins:
- GitHub Actions to immutable commit SHAs;
- Python, Node, nginx and PostgreSQL container bases to immutable sha256 digests.

A CI check prevents regression to floating Action tags or unpinned container bases.

Dependency lockfiles are committed:
- `requirements-prod.lock.txt`;
- `requirements-dev.lock.txt`;
- `frontend/package-lock.json`.

Backend production image installation is constrained by the production lock. CI development installation is constrained by the development lock. Frontend CI and image builds use `npm ci`.
