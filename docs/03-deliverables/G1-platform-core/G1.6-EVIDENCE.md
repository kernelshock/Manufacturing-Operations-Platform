## Implemented
A browser-based application shell now consumes the versioned MOP REST API without direct database access.

The G1.6 shell provides:
- secure local-session login;
- startup session validation through `/api/v1/auth/me`;
- backend metadata and readiness status;
- permission-driven module visibility;
- organization / plant context selection when the effective permissions allow global discovery;
- read-only audit surface for users with `audit.read`;
- administration shell for `admin.users` / `admin.roles`;
- explicit placeholders for APS, MES, Kanban, Maintenance and Purchasing;
- responsive desktop/tablet baseline.

## Security boundary
The frontend uses effective permission codes only to shape the user experience. It is not an authorization authority.

All privileged actions remain enforced by FastAPI server-side RBAC. Hiding a navigation item is never treated as a security control.

Browser requests use `credentials: include` so the opaque HttpOnly session cookie remains the authentication mechanism. No raw session token is stored by frontend JavaScript.

## Development topology
Vite proxies:
- `/api` -> local FastAPI;
- `/health` -> local FastAPI.

This preserves same-origin browser behavior in DEV without weakening the backend cookie/session model.
