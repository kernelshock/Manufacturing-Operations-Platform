## Objective

Expose the authoritative published APS schedule as a read-only Gantt projection and provide a frontend surface for master/per-plan visualization without introducing a second planning engine in the browser.

G4.6 introduces no new persistence identity or migration.

Implemented backend projection:
- read-only `GET /api/v1/aps/gantt`;
- optional `plan_id` filter;
- MASTER scope across all CURRENT publications;
- PLAN scope for one ProductionPlan;
- projection only from immutable `SchedulePublication.status = CURRENT` snapshots;
- complete operation provenance through Plan, Taquilla, ProductLine, Article, RoutingRevision, RoutingOperation, Resource, WorkCenter and Area;
- published planned start/finish and productive segments;
- publication version/fingerprint/run/scenario metadata;
- counts for operations, Taquillas and resources;
- explicit constraint evaluation state.

Evaluated constraints exposed:
- routing precedence;
- resource finite capacity;
- manufacturing calendar;
- configured breaks;
- off-shift time.

Explicitly not evaluated until later gates:
- materials;
- maintenance;
- workforce.

## Frontend

APS is now a real permission-driven module rather than a future placeholder.

Implemented:
- navigation module `APS / Gantt` protected by `aps.read | aps.edit`;
- master schedule view;
- per-plan selector;
- zoom/scale selector: Hour / Shift / Day;
- horizontal scroll for large planning horizons;
- grouping by Plan / Taquilla;
- operation labels with article, resource and WorkCenter context;
- published schedule metrics;
- evaluated/not-evaluated constraint visibility;
- operation envelope from authoritative `planned_start/planned_finish`;
- productive segments rendered inside the envelope;
- non-working gaps remain visibly empty inside an operation envelope.

The frontend derives only visual coordinates from backend timestamps. It never recalculates precedence, capacity, resource selection, duration or publication state.

## Break / continuity semantics

A scheduled operation spanning lunch is represented as:
- one published operation envelope;
- multiple productive segments;
- an empty visual gap for the non-working period.

Therefore the Gantt can show continuity across lunch/off-shift periods without misrepresenting those periods as productive capacity.
