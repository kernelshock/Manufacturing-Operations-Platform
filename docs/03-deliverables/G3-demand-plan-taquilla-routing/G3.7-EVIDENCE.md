## Backend operational projection
Added:
GET `/api/v1/demand/plans/{plan_id}/projection`

Protected by:
`demand.read`.

The endpoint returns one stable view for operator/reporting clients rather than forcing the browser to reconstruct business joins.

Plan projection includes:
- canonical Plan identity and business number;
- Plan lifecycle/status;
- historical completion classification;
- cancellation reason;
- ordered Taquillas;
- aggregate Taquilla count;
- aggregate product-line count;
- total missing-routing count;
- blocked DRAFT Taquilla count.

## Taquilla projection
Each Taquilla exposes:
- UUID and business code;
- sequence inside Plan;
- lifecycle status;
- SIMPLE / DOUBLE_DECK topology;
- historical completion classification;
- cancellation reason;
- ordered product lines;
- product count;
- total requested quantity;
- bound-routing count;
- missing-routing count.

A DRAFT Taquilla is surfaced as blocked when:
- it has no product composition; or
- one or more product lines do not have an exact routing binding.

This blocker metric is an operational readiness signal only. It is not an APS capacity or scheduling decision.

## Product / Routing projection
Each product line exposes:
- exact G2 Article UUID;
- Article external code;
- canonical Article description;
- requested Decimal quantity;
- explicit SINGLE / UPPER / LOWER deck position;
- source document key;
- source line key;
- exact RoutingRevision UUID when bound;
- binding mode RESOLVED / OVERRIDE;
- routing revision number;
- routing status;
- routing effective timestamp;
- override reason when applicable.

The projection references G2 identities. It does not duplicate master data.

## Controlled import workflow
Users with `demand.edit` receive a normalized Taquilla JSON import surface.

The frontend:
- accepts JSON;
- calls the G3.6 normalized assimilation endpoint;
- displays APPLIED or review-required outcome;
- refreshes Plan/import state.

The frontend does **not**:
- parse PDFs;
- infer floor from filename/order;
- infer product mappings;
- bypass backend validation;
- bypass backend RBAC.

Backend validation remains authoritative.

- finite-capacity scheduling;
- operation sequence dates;
- operation planned start/finish;
- resource allocation decisions;
- Gantt state;
- shop-floor actual start/finish;
- actual produced quantity;
- scrap or MES events.
