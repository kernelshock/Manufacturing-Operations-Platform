## Assimilation pipeline
The pipeline separates source staging from operational demand.

1. Receive normalized source contract.
2. Compute deterministic payload fingerprint.
3. Detect exact idempotent replay.
4. Stage batch/document/line evidence.
5. Validate Plan identity and lifecycle.
6. Validate Taquilla identity and sequence.
7. Validate document provenance.
8. Resolve every product to an exact active G2 FINISHED_PRODUCT Article.
9. Validate explicit vehicle/deck semantics.
10. Detect duplicates and competing imports.
11. Quarantine with issues when any blocker exists.
12. Apply to operational Taquilla/ProductLine records only when fully validated.
13. Persist source-to-target UUID provenance.

No partially valid batch creates partial operational demand.

## Source documents
Each batch accepts one or two source documents.

Each document preserves:
- source document key;
- filename;
- SHA-256;
- optional exported timestamp.

Duplicate document keys or duplicate hashes inside one payload are rejected by schema validation.

Reuse of a document SHA-256 in another assimilation batch from the same source system creates a BLOCKER issue.

## Source product lines
Each line preserves:
- source document key;
- globally unique source line key inside the batch;
- source article system;
- source article code;
- exact resolved G2 Article UUID when available;
- Decimal requested quantity;
- explicit deck position;
- generated target product-line UUID after successful apply.

Requested quantity must be submitted as a decimal string and must be positive.

## Explicit topology
SIMPLE:
- every line must be SINGLE.

DOUBLE_DECK:
- SINGLE is rejected;
- UPPER must be represented;
- LOWER must be represented.

A DOUBLE_DECK Taquilla can be represented by:
- one unified source document containing explicit UPPER and LOWER lines; or
- two source documents.

Document identity and document order have no floor semantics.

A line in DOC-A may be LOWER and a line in DOC-B may be UPPER. The system uses only the explicit deck_position field.

## Product resolution
Each source product resolves by exact:
- source article system;
- source article code.

The resolved G2 Article must:
- exist;
- be active;
- have article_kind = FINISHED_PRODUCT.

If not, the source line remains staged and a BLOCKER issue is recorded.

No Article, ProductConfiguration or product identity is invented by G3.

## Duplicate controls
The pipeline blocks:
- an already existing operational Taquilla code;
- an already occupied Taquilla sequence inside the target Plan;
- a source document already used in another assimilation batch;
- another non-rejected assimilation batch claiming the same Taquilla code;
- another non-rejected assimilation batch claiming the same Plan sequence.

This closes the race between duplicate staged loads before either one reaches operational apply.

## Idempotency
Identity is based on:
- source_system;
- deterministic normalized payload fingerprint;
- parser_version.

Exact replay:
- returns the existing assimilation batch;
- returns the same target Taquilla UUID when already applied;
- does not create duplicate staging rows;
- does not create duplicate operational demand;
- reports `idempotent_replay = true`.

A changed payload is not treated as the same import and must pass duplicate controls independently.

## Quarantine
A batch with any BLOCKER becomes REVIEW_REQUIRED.

Examples:
- unmapped product;
- inactive/non-finished product;
- reused source document;
- duplicate Taquilla identity;
- competing assimilation identity.

REVIEW_REQUIRED batches preserve source evidence but have:
- no generated Taquilla;
- no generated operational product lines.

## Apply
Only VALIDATED batches are applied.

Operational apply creates:
- one DRAFT Taquilla;
- explicit SIMPLE/DOUBLE_DECK topology;
- ordered product lines;
- exact Article references;
- Decimal quantities;
- source_line_key;
- source_document_key;
- explicit deck_position.

After successful apply:
- batch status becomes APPLIED;
- target_taquilla_id is persisted;
- each staged line receives target_product_line_id.
