## Taquilla topology
New Taquilla field:
`vehicle_topology`

Allowed values:
- `SIMPLE`;
- `DOUBLE_DECK`.

New Taquillas default to SIMPLE for compatibility with the existing G3.1/G3.2 operator flow.

Topology can be changed only while the Taquilla is DRAFT and before any product composition line exists. This prevents changing the structural interpretation of already-entered demand.

## Product-line deck allocation
New product-line field:
`deck_position`

Allowed values:
- `SINGLE`;
- `UPPER`;
- `LOWER`.

Cross-entity service rules:
- SIMPLE Taquilla → only SINGLE is valid;
- DOUBLE_DECK Taquilla → only UPPER or LOWER is valid.

For DOUBLE_DECK, omitting explicit floor assignment is rejected because the backward-compatible line default is SINGLE, which is invalid for that topology.

## Source-document grouping
New optional product-line field:
`source_document_key`

Purpose:
- preserve which source document a line came from;
- support one-document or two-document Taquilla representations;
- prepare G3.6 assimilation.

It is deliberately independent from deck position.

Therefore:
- DOC-A does not mean UPPER;
- first document does not mean UPPER;
- second document does not mean LOWER;
- one document may contain both UPPER and LOWER lines;
- different documents may contribute to the same deck.

No floor inference is permitted from document order or identity.

- create Routing/BOP definitions;
- schedule floor work independently;
- assign APS resources/timestamps;
